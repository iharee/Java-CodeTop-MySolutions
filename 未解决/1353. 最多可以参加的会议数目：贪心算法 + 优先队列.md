题目简述：

> 给你一个数组 `events`，其中 `events[i] = [startDayi, endDayi]` ，表示会议 `i` 开始于 `startDayi` ，结束于 `endDayi` 。
>
> 你可以在满足 `startDayi <= d <= endDayi` 中的任意一天 `d` 参加会议 `i` 。在任意一天 `d` 中只能参加一场会议。
>
> 请你返回你可以参加的 **最大** 会议数目。

题目链接：[1353. 最多可以参加的会议数目](https://leetcode.cn/problems/maximum-number-of-events-that-can-be-attended/)

# 思路Ⅰ

原本我考虑的是普通区间排序，即优先按左端点升序排序、其次按右端点升序排序一次，然后对排序后的区间们进行静态地遍历，并且在该过程中使用贪心算法计数。在该逻辑下，我们尽可能地参加起始时间最早的会议，如果有多个会议起始时间相同，则优先参加截止时间最早的会议。就单调性而言，这样似乎能最大化利用时间。

> 事实上也的确如此，但前提是不存在起始时间相同的会议。下文会说明为什么当起始时间相同时，这一简单的逻辑会出问题。

但在编码并提交测试后，发现无法完全 AC。对于一些测试用例，比如 `[[1,2], [1,5], [2,2]]`，我的算法会得到错误结果。这种情况下，应当优先在第二天参加 `[2,2]` 的会议，但我们的算法会先在第一天参加 `[1,2]` 的会议、然后在第二天参加 `[1,5]` 的会议，于是就错过了 `[2,2]` 的会议。

通过这一简单的测试用例，我隐约意识到问题出在于我的区间排序只做了一次，是静态的，但我们参加了一场会议后，实际上剩余会议对于我们的最早可参加时间也发生了变化，这是一个动态的过程，需要想办法动态维护。

> 注：不可以按会议持续时间排序，然后实现优先参加会议时间最短会议的算法。因为那样的话会导致算法的复杂度和会议的起止时间有关，而且也不好实现。不过，在分析简单例子时，可以按这个思路进行分析。

如何理解所谓「动态维护」呢？比如，还是 `[[1,2], [1,5], [2,2]]` 的例子，我们参加完第一天会议后，剩余的会议是 `[[1,5], [2,2]]`。但要知道，在第一天参加了会议 `[1,2]` 后，我们下次可参加会议的时间已经来到了第二天，尽管 `[[1,5], [2,2]]` 符合「<u>优先按左端点升序排序、其次按右端点升序排序</u>」的区间排序逻辑，可是此时我们已经不可能回到第一天同时参加会议 `[1,5]` 了，因此左端点的 `1` 实际上是一个无效值，<u>我们应该把会议 `[1,5]` 更新为 `[2,5]`，让 `[2,5]` 与 `[2,2]`「同台竞争」</u>。显然，按照我们的区间排序逻辑，这时应当首先参加 `[2,2]`——很好，这就对了！

但是我们不可能每参加一个会议就更新所有会议的起始时间，然后再重新做一次排序，这样做代价太大。在下文将具体分析原因。

下面是按上述原先的思路所实现的错误代码：

```java
class Solution {
    public int maxEvents(int[][] events) {
        Arrays.sort(events, (a, b) -> {
            if (Integer.compare(a[0], b[0]) != 0) return Integer.compare(a[0], b[0]);
            return Integer.compare(a[1], b[1]);
        });

        int count = 0;
        int d = 0;  // 下一次可参加会议的最早时间
        for (int[] event : events) {
            if (d <= event[1]) {
                d = Math.max(d, event[0]) + 1;
                count++;
            }
        }

        return count;
    }
}
```

按上述思路实现的上述算法是错误的，在许多情况下无法得到正确的结果。

# 思路Ⅱ

事实上，要实现「动态」，我们要做的是跳出只做一次全局排序的经典区间排序问题的定式思维——考虑优先队列（最小堆、小顶堆），一个具有动态排序特征的数据结构。

当然，意识到应使用优先队列后，怎么把优先队列用对，也是个问题。可以考虑让区间们按「<u>优先按左端点升序排序、其次按右端点升序排序</u>」的优先队列顺序排序，在遍历的过程中用优先队列维护当前可参加的会议。

按前文的想法，最简单的思路当然是参加一次会议后，在优先队列中弹出相应的区间，然后按优先队列的规则，接下来 `peek()` 得到的区间是「最可能的」起始时间早于或等于当前参会日期（从而冲突）、需要更新左端点以保证在新情况下被正确排序的区间。

按照这样的想法，可以实现下述算法：

```java
class Solution {
    public int maxEvents(int[][] events) {
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> {
            int r = Integer.compare(a[0], b[0]);
            if (r != 0) return r;
            return Integer.compare(a[1], b[1]);
        });

        for (int[] event : events) pq.offer(event);
        int day = 0;
        int res = 0;
        while (!pq.isEmpty()) {
            int[] event = pq.poll();
            if (event[1] < day) continue;
            res++;
            day = Math.max(day, event[0]) + 1;

            while (!pq.isEmpty() && pq.peek()[0] == event[0]) {
                int[] renewal = pq.poll();
                renewal[0] = day;
                pq.offer(renewal);
            }
        }

        return res;
    }
}
```

这份代码实现从正确性上而言是没问题的，但算法的最坏时间复杂度为 $O(n^2\log n)$，空间复杂度为 $O(n)$，其中最坏时间复杂度在大量区间都具有相同左端点但右端点不同时达到。

考虑到本题目 `1 <= events.length <= 10^5` 的数据范围，该时间复杂度是不可接受的，对于精心构造的测试用例会超时。显然，`while (!pq.isEmpty() && pq.peek()[0] == event[0])` 的更新是关键的，但是也带来了大量的可能时间开销，我们应该换种实现方式。

# 思路Ⅲ

新思路的正确性已经可以证明了，我们要解决的只是 `while (!pq.isEmpty() && pq.peek()[0] == event[0])` 带来的高昂时间成本。如何避免不断地弹出区间、更新再放回优先队列呢？

这就需要转变思维了：实际上，我们在执行的是一种 <b><u>贪心策略</u></b>—— <b><u>对于今天可参加的所有会议，优先选择结束时间最早的会议参加</u> </b>。只不过，在过去，为了维护「对于今天可参加的所有会议」，我们的做法是把所有未来会议都放到优先队列中，然后再在优先队列里更新、维护会议的最早可参加时间。这带来了相当大的额外开销。

但其实，我们完全可以只在优先队列中放入今日可参加的会议，然后使优先队列按区间右端点的顺序排序。弹出区间，如果区间已过期，则此时什么都不用做，这实际上是一种懒删除；如果区间未过期，则参加会议。

```java
class Solution {
    public int maxEvents(int[][] events) {
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> {
            int res = Integer.compare(a[0], b[0]);
            if (res != 0) return res;
            return Integer.compare(a[1], b[1]);
        });

        for (int[] event : events) pq.offer(event);
        int day = 0;
        int res = 0;
        while (!pq.isEmpty()) {
            int[] event = pq.poll();
            if (event[1] < day) continue;
            res++;
            day = Math.max(day, event[0]) + 1;

            while (!pq.isEmpty() && pq.peek()[0] == event[0]) {
                int[] renewal = pq.poll();
                if (renewal[1] >= day) {
                    renewal[0] = day;
                    pq.offer(renewal);
                    break;
                }
            }
        }

        return res;
    }
}
```
